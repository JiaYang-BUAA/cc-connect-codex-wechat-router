这是 `cc-connect` 与 Codex Desktop 的 Windows 本机伴随服务。它按“置顶任务”或
“最近活跃的 10 个任务”模式，把 Codex 最终答复推送到既有微信会话，并把微信的引用回复路由回原任务。

本仓库不包含任何令牌、数据库、任务记录、微信会话或 cc-connect 上游源码。
面向普通用户的 GitHub Release 已包含经过校验的定制 `cc-connect.exe`；其 Go
源码仍维护在作者 fork 的 `quote-router` 分支，并在每个发行包中记录固定提交。

> 当前稳定版本：通知器 `1.4.0`，配套 cc-connect 路由补丁 `v1.4.1+qr16`。

## 功能

- `/rwmode` 在两种推送模式间切换：置顶任务（默认），或最近有过对话活动的 10 个未归档任务（包括空闲任务）。
- 置顶模式保留单独置顶任务、置顶定时任务和 `/rwfolder` 置顶文件夹推送功能。
- 识别 Codex 定时任务的新运行结果，引用回复会回到该定时任务的目标对话；临时运行任务不重复占用最近任务名额。
- `/rw` 显示 5h/7d 剩余额度和刷新时间，以及当前模式的任务列表、运行时长和排队数。
- 5h 或 7d 剩余额度首次降至 10%以内、以及进一步降至 0%时，主动发送一次微信提醒；额度恢复后自动重新布防。
- `/rw3 内容` 投递到当前任务列表的第 3 项；`/rw3 /y 内容` 直接提交。最近模式的编号固定对应最近一次返回的列表，发送 `/rw` 才刷新。
- 引用最终答复时，任务运行中默认排队；引用排队提示回复 `/y` 可直接提交原消息。
- 普通排队消息会写入 Codex Desktop 原生排队列表，显示在输入框上方；可在
  Desktop 中编辑、排序或删除，通知器队列只在原生通道不可用时回退使用。
- `/rwpush` 是两种模式共用的最终答复推送总开关；引用语音使用微信识别出的文本。
- `/hp` 在微信内显示面向新手的完整操作指南。
- 持久化队列、退避重试、去重、仅回环 HTTP 路由和健康检查。

## 运行要求

- Windows 10 或 Windows 11。
- Python 3.11 或更高版本；通知器运行时只使用 Python 标准库。
- 已登录的 Codex Desktop，且本机任务数据库和 CDP 调试端点可用。
- 首次安装时可扫码登录微信；不需要另外下载或构建 cc-connect。
- PowerShell 7 推荐用于安装、构建和诊断脚本。

## 快速开始

普通用户只需要访问本仓库，不需要打开 cc-connect Fork：

1. 在本仓库的 [Releases](https://github.com/JiaYang-BUAA/cc-connect-codex-wechat-router/releases/latest)
   下载 `windows-x64.zip` 和同名 `.sha256` 文件。
2. 校验 ZIP 后解压：

   ```powershell
   $zip = Get-Item .\cc-connect-codex-wechat-router-*-windows-x64.zip
   $expected = ((Get-Content "$($zip.FullName).sha256") -split '\s+')[0]
   (Get-FileHash $zip.FullName -Algorithm SHA256).Hash.ToLower() -eq $expected
   Expand-Archive $zip.FullName -DestinationPath .\cc-connect-router
   Set-Location .\cc-connect-router
   ```

   校验结果必须为 `True`。

3. 进入解压后的目录并运行引导安装器：

   ```powershell
   pwsh -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
   ```

安装器会自动完成以下操作：

- 校验并安装发行包内固定版本的 `cc-connect.exe`；
- 首次使用时显示微信二维码，扫码完成机器人登录；
- 自动发现 Codex、Python 和本地任务数据库；
- 为 cc-connect 和通知器写入同一个随机路由令牌；
- 修改配置前建立时间戳备份；
- 注册并启动 `cc-connect` 与 `Codex Pinned WeChat Notifier` 计划任务。

如果 cc-connect 配置里有多个微信项目，使用项目名重新运行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -CcProject '项目名'
```

首次运行只建立偏移基线，不补发历史消息。高级用户仍可使用
`config.example.json`、`install.ps1` 和文末的源码构建命令进行手动安装。

安装完成后，在微信发送 `/rw`。能看到额度、推送模式和任务状态回复，即表示状态路由、微信回复和通知器均已连通。

> **每次开始使用前建议先发送 `/rw`。** 尤其是较长时间没有和机器人交互、准备从微信投递新任务或等待 Codex 最终答复时，请先发送 `/rw`，等机器人返回状态后再继续操作。这条微信入站消息会激活当前交互上下文，并提供一次正常的被动回复机会，有助于后续通知送达；但它不是永久保活，也不能保证立即解除微信网关已经施加的主动推送限制。

## 微信命令

```text
/rw                         查看当前模式的任务列表和额度
/rwmode                     切换置顶 / 最近活跃 10 个任务模式
/rwmode pinned              使用置顶任务模式（默认）
/rwmode recent              使用最近活跃 10 个任务模式
/rw3 内容                   向当前任务列表第 3 项提交内容
/rw3 /y 内容                向当前任务列表第 3 项直接提交内容
/rwpush                     开关当前模式的最终答复推送（共用总开关）
/rwfolder                   开关置顶文件夹内对话推送（仅置顶模式）
/hp                         查看详细使用指南
```

## 使用指南

### 首次使用

1. 确认 Codex Desktop 已登录。默认使用置顶模式，请先置顶需要操作的普通任务或定时任务；也可以稍后发送 `/rwmode recent` 改用最近活跃任务。
2. 确认 `cc-connect` 和本通知器都已启动；可运行 `notifier.py --selftest` 检查配置和本地路由。
3. 每次开始使用或长时间没有交互后，先在微信中发送 `/rw` 激活当前交互上下文。通知器会显示 Codex 的 5h/7d 剩余额度和刷新时间，再按当前推送模式列出任务编号、运行状态和运行时长。
4. 记住任务编号后，可以用 `/rw编号 内容` 直接向该任务发送新消息。

### 查看状态

发送 `/rw` 可以查看 5h/7d 剩余额度、对应刷新时间、推送模式和当前任务列表。运行中的任务显示当前处理时间，未运行的任务显示“空闲”；没有符合条件的任务时仍会显示额度和推送开关，并提示列表为空。额度暂时读取失败时会显示“Codex额度：暂时无法读取”，不影响下面的任务状态。

置顶模式按 Codex Desktop 当前侧边栏的单独置顶顺序编号，包括单独置顶的定时任务；任务取消置顶或归档后，编号可能变化。最近模式按最近活动时间排序，并保存本次返回的编号列表，避免新活动改变你刚看到的编号。

### 选择推送模式

发送 `/rwmode` 可在两种模式间切换，也可以直接指定：

- `/rwmode pinned`：置顶任务模式，默认启用。推送单独置顶、未归档任务的最终答复；如果 `/rwfolder` 已开启，还会推送置顶文件夹内任务的答复。
- `/rwmode recent`：最近活跃任务模式。按 Codex 记录的最近对话活动时间，从新到旧选取最多 10 个未归档用户任务。用户消息和任务答复都属于活动，当前空闲的任务也会入选；这里指 10 个任务，不是 10 条消息，也不是仅选正在运行的任务。

子代理任务不计入最近列表。定时任务的临时运行会关联回对应目标任务，不额外占用一个名额。

切换模式后会返回新的任务列表。最近模式的**推送名单会随活动动态更新**，但 `/rw编号 内容` 使用最近一次 `/rw` 或模式切换返回的编号列表；需要更新编号时，再发一次 `/rw`。例如，刚看到第 3 项为“科研”后，即使其他任务变得活跃，`/rw3 内容` 仍会发送给“科研”，直到你刷新列表。

两种模式共用 `/rwpush` 总开关，切换模式不会改变其开关状态，也不会补发新入选任务的历史答复。切换前已接收的指令、排队消息和积压通知会保留并继续处理。

### 额度提醒

5h 或 7d 剩余额度从 10%以上首次降至 10%以内时，通知器会主动发送一次微信提醒；额度进一步降至 0%时再提醒一次。每条提醒同时显示两个额度的当前百分比和本地刷新时间。额度在同一区间继续下降、通知器轮询或服务重启都不会重复提醒；额度恢复到 10%以上后，下一轮低额度提醒会重新生效。

额度提醒独立于 `/rwpush` 和 `/rwfolder`，关闭最终答复推送不会关闭额度提醒。通知器默认每 60 秒读取一次额度，并使用常驻的本地 Codex App Server 连接；微信发送失败时不会提前标记为已提醒，后续轮询会继续尝试。状态文件只保存百分比、刷新时间和告警阶段，不保存账号或认证令牌。

### 回复 Codex 最终答复

收到形如“【聊天名称】”的最终答复通知后，直接引用整条通知并发送文字即可。任务空闲时会立即提交；任务正在处理时，消息默认进入队列，微信会返回前方排队数量。

默认排队时，消息会直接出现在对应 Codex Desktop 任务输入框上方的原生排队列表中，之后由 Desktop 自己按顺序提交。你可以在 Desktop 中修改、调整顺序或删除这条消息；微信端仍会保留一条跟踪记录，用于识别“引用排队提示回复 `/y`”的操作。若 Desktop 原生队列暂时不可用，通知器会自动使用自己的持久化回退队列。

“已提交”表示 Desktop 已确认接收或已确认加入原生队列，不表示任务已经执行完成。若转交失败，会显示“已保存消息，等待转交 Codex”，消息保留在通知器内自动重试，不需要重复发送。若提交结果不确定（例如响应超时），会先核对原生队列和任务记录，再决定是否重试，避免重复提交。

新版 Desktop 的服务端原生队列与旧版的本地队列分别适配；不会把新版服务端队列改写为旧的本地队列。队列提交独立于 Desktop 中设置的默认发送方式。Desktop 内部接口仍可能随版本变化，遇到兼容故障时请保留等待中的消息并检查日志，不要连续重发。

排队确认会在“当前队列”下面按执行顺序列出该任务每条排队消息的内容，包括本次刚提交的消息。多行内容会折叠为一行；内容过长或队列过多时会截断显示，但不修改 Codex Desktop 中保存的原消息。

如果需要跳过队列，在消息前加 `/y`，例如 `/y 请优先检查这个错误`。直接提交失败时，系统会自动退回队列，不会丢失消息。

排队确认消息也可以被引用，引用后只发送 `/y`，即可把原来排队的那条消息改为直接提交。引用内容必须是完整的通知或排队确认；无法识别时，系统会提示重新引用最近一次完整 Codex 答复。

两种模式下，只要通知仍有保存的路由记录，引用通知都会回到原任务，不受模式切换、取消置顶或掉出最近 10 个任务影响。已归档、已删除或不可用的任务仍不能提交；无法识别的引用不会猜测目标任务。推送模式只控制主动推送范围，不改变旧通知的引用目标；范围外任务可以收到引用回复，但其最终答复仍按当前推送范围决定是否发送到微信。

### 按编号继续对话

当历史通知不方便查找时，使用 `/rw编号 内容`，例如：

```text
/rw3 请根据上一版结果继续分析
```

这会把消息发送到当前任务列表的第 3 项。需要直接提交时使用 `/rw3 /y 内容`。置顶模式使用当前置顶顺序；最近模式使用最近一次 `/rw` 或模式切换返回的编号，即使任务随后掉出前 10，也不会把这个编号悄悄改给其他任务。任务已归档，或在置顶模式下已不属于允许回复的置顶范围时，系统会提示无法继续回复。

### 控制通知推送

发送 `/rwpush` 可切换两种模式共用的最终答复推送总开关，微信会返回当前模式下推送已开启或关闭的提示。切换模式不会自动打开或关闭推送。关闭推送只影响最终答复通知，不会停止 Codex 任务、清空队列或禁用微信提交。

在置顶模式发送 `/rwfolder`，可单独开启或关闭置顶文件夹内对话的最终答复推送。此开关默认关闭，并受 `/rwpush` 总开关控制；开启后，只要未归档对话属于当前置顶文件夹，即使对话本身没有单独置顶，完成后也会推送。通知可以照常引用并回复到原对话。置顶模式的 `/rw` 编号列表仍只包含单独置顶的对话，以免文件夹内大量历史对话占用编号。

最近模式不使用置顶文件夹开关。在该模式发送 `/rwfolder` 只会提示此功能仅在置顶模式生效，不会修改原设置；切回置顶模式后继续使用之前的文件夹开关状态。

置顶模式下，单独置顶的定时任务不依赖 `/rwfolder`，与普通单独置顶任务一样受 `/rwpush` 总开关控制。通知器只推送新完成且属于当前推送范围的定时运行，不补发历史运行结果。Codex 会为一次定时运行创建临时运行任务并自动归档；通知器会把结果关联到定时任务目标，因此引用通知或按当前列表使用 `/rw编号 内容` 时仍能继续对应目标对话。

### 微信交互激活、主动推送限制与积压消息汇总

`context_token` 是微信网关随用户消息下发的临时回复凭证。cc-connect 发送消息时需要携带当前会话的令牌。它不是微信登录凭证、Codex API Key 或 Codex 额度令牌，也不会影响 Codex 任务本身是否继续运行。

当你给机器人发送微信消息时，微信网关可能下发新的 `context_token`，同时这条入站消息允许机器人走正常的被动回复路径。cc-connect 会缓存令牌供后续使用，但本地保存不能延长服务器端有效期；持续执行 `getUpdates` 长轮询也只负责收消息，不会刷新交互上下文或主动推送额度。目前微信网关没有公开可调用的续期接口，也没有公开固定的有效期或主动推送额度。

根据小红书等社区中的使用经验，用户发送一条消息激活交互后，机器人在这一轮交互中最多可主动发送约 **10 条**消息。这个数字不是腾讯公开接口文档承诺的固定额度，也不能视为每个账号都一定能发送满 10 条；实际可发送数量可能因账号状态、发送频率、时间间隔和微信风控而更少。本项目将“最多约 10 条”作为使用风险提示，而不是可依赖的发送保证。

因此，**每次准备使用微信控制 Codex 时，请先发送 `/rw`，等状态消息返回后再投递任务。** 长时间未交互后也应重新发送 `/rw`。这能激活一次新的微信交互并提高随后通知成功的概率，但不能作为永久保活，也不能保证立即解除已经触发的服务端限制。不要通过定时发送机器人心跳消息保活：心跳本身属于主动推送，可能更快消耗推送预算。

受限时通常会出现以下现象：Codex 对话已经完成，但微信没有收到最终答复；通知器或 cc-connect 日志出现 `ret=-2`、`prepare failed`、`expired context_token` 或“需要用户重新发送消息”的错误。`ret=-2` 本身并不能证明令牌过期；当前 cc-connect 上游将其视为机器人级主动推送节流。无论具体原因是哪一种，这都不是 Codex 任务失败或 Codex 额度耗尽，而是微信暂时没有接受这次发送。

通知器遇到这类错误后会执行以下保护逻辑：

1. 立即停止继续逐条推送答复，避免令牌恢复后大量历史消息刷屏。
2. 将令牌失效期间完成的答复保留为积压记录；答复正文仍完整保存在原 Codex 对话中。
3. 按聊天名称统计积压数量，不把任何答复正文写入汇总消息。
4. 你下一次给机器人发送任意微信消息后，微信通常会下发新凭证，通知器会立即尝试发送一条积压消息汇总；只有汇总发送成功后才清除对应推送记录。如果微信仍未接受新凭证，积压记录会继续保留，之后再重试。

汇总格式示例：

```text
积压消息汇总

【科研】2条
【日常】1条
```

汇总消息只说明哪些对话有多少条答复，不代表这些答复丢失。请进入对应 Codex 对话查看完整内容；需要从微信继续某个对话时，可发送 `/rw编号 内容`。由于一条汇总可能包含多个对话，它本身不能作为某一个具体对话的引用路由。

## 工作原理

```text
Codex Desktop 数据库和任务记录
             |
         notifier.py ---- 本机 HTTP 路由（仅 127.0.0.1）
             |                         |
       最终答复推送              微信引用和命令
             |                         |
             +------ cc-connect ------+
```

通知器从 Codex Desktop 的全局状态读取置顶顺序、置顶文件夹及对话归属，并从任务记录读取最近活动时间。置顶模式按当前置顶顺序编号，最近模式按最近一次返回的列表固定编号；两者都不是任务的永久 ID。路由服务只监听回环地址，答复正文和访问令牌不会写入日志。

## 常见问题

### `/rw` 显示没有任务

置顶模式下，先在 Codex Desktop 侧边栏置顶至少一个未归档普通任务或定时任务，然后等待数秒再试；也可以发送 `/rwmode recent` 查看最近有过对话活动的任务。最近模式下，请确认 Desktop 中存在未归档的用户任务，然后发送 `/rw` 刷新。任务列表来自 Codex Desktop 本地记录，不读取 cc-connect 自己创建的独立会话。

### 微信命令没有反应

确认两个计划任务都在运行：

```powershell
Get-ScheduledTask -TaskName 'cc-connect','Codex Pinned WeChat Notifier' |
  Select-Object TaskName, State
```

随后运行自检，并检查 `logs/notifier.log` 与 `%USERPROFILE%\.cc-connect\logs\daemon.log`。不要在 Issue 中粘贴令牌、完整用户 ID、对话正文或本机数据库。

### 引用后无法路由到原对话

请引用完整的 Codex 最终答复通知。转发、手动复制或截断后的文本可能缺少路由指纹；这种情况下使用 `/rw编号 内容` 继续对话。

### 手机和电脑微信换行不同

微信不同客户端会压缩普通空行。通知器会在最终答复、排队列表和 `/rw` 各区块之间加入不可见占位行，优先保证手机端分段清楚；电脑端可能显示得更紧凑，但不影响阅读和路由。
